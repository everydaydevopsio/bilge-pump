# Field test: Bilge v2.2.3 driven by Claude Code (2026-11-26)

A Claude Code session used Bilge to free disk space on a developer Mac. This report records what was run, what happened, and the evidence behind each finding. The fix plan is [MAP-0064](../plans/MAP-0064_field_test_fixes.md).

## Environment

| Item | Value |
| --- | --- |
| Bilge | v2.2.3, commit `06a65b1`, installed via Homebrew cask |
| OS | macOS 15 (Darwin 24.5.0), arm64 |
| Docker runtime | OrbStack (active context `orbstack`); remote `ssh://` contexts also configured |
| Disk | Data volume 460 GiB, 7.6 GiB free (99%) at start |
| Config | `~/.config/bilge-macos/config.yaml` generated by an older release; `~/.config/bilge-pump/config.yaml` lists tasks `dev-cache, git-cleaner, mac-cache-cleaner`, `scanPath: ~/src` |
| Repo layout | `~/src/<org>/<repo>` (repos at depth 2–3) |

## Outcome

Free space went from 7.6 GiB to 15.6 GiB. Only about 2 GB of that came through Bilge. The rest needed manual commands, because Bilge measures paths it cannot clean (Gradle, Xcode DerivedData) and because the local docker target was unsafe.

## Findings with evidence

IDs match the plan.

### F1 — MCP rejects every call from Claude Code (P0)

`cmd/bilge/mcp.go` decodes the whole `tools/call` `params` object with `decodeMCPObject`, which calls `DisallowUnknownFields()`. The MCP spec allows `params._meta`, and Claude Code always sends it (`progressToken`, `claudecode/toolUseId`). The error message hides the decoder error.

Repro:

```sh
printf '%s\n' \
 '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"1"}}}' \
 '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
 '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"bilge_check_tools","arguments":{"targets":"npm"}}}' \
 '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"bilge_check_tools","arguments":{"targets":"npm"},"_meta":{"progressToken":3}}}' \
 | bilge mcp
# id 2 -> result; id 3 -> {"code":-32602,"message":"tools/call requires a tool name and object arguments"}
```

### F2 — Generated config freezes old, unsafe defaults (P0)

The user config is a full snapshot of defaults from an older release. Built-in defaults on `main` have since been fixed, but the snapshot overrides them:

| Target | User config (stale) | Built-in default on `main` |
| --- | --- | --- |
| docker | `docker system prune -af --volumes`; notes say "safe CLI prune only" | `docker system prune -af`; "named volumes are preserved" |
| puppeteer | `sh -c "npm install -g puppeteer ... trimCache()"` | no command; "cleanup must not install packages" |
| ollama | `ollama list` | no command; informational |

At scan time there were 16.4 GB of Docker volumes (88 total, 2 active), likely dev databases.

> **Correction (code review, 2026-11-26):** these entries were read from the config file, not from what would execute. On v2.2.3, `loadConfigWithDefaults` already drops docker `--volumes` (unless `--docker-prune` or `options.dockerPruneByDefault: true`), puppeteer's `sh -c` install command and android's `sdkmanager --update` from *any* config before running it. So the stale config would not have pruned volumes. The remaining F2 problems: stale configs silently diverge from defaults (`ollama list`, notes, new targets and fixes that aren't filtered), and safety depends on a hard-coded filter list rather than the config model.

### F3 — Docker cleanup ignores the active context and runtime (P0)

`docker context ls` showed `ssh://` contexts. Bilge runs `docker ... prune` against whatever context is active and never shows it. Docker paths assume Docker Desktop (`~/Library/Containers/com.docker.docker/...Docker.raw` did not exist). OrbStack data (`~/Library/Group Containers/*.dev.orbstack/data`, 37 GB) was not recognised. Space freed inside a VM does not return to the host right away; Bilge doesn't say so.

### F4 — Android "clean" command updates the SDK (P0)

> **Correction (code review, 2026-11-26):** `sdkmanager --update` is still listed in the built-in default and in generated configs, but `loadConfigWithDefaults` drops it before any command runs, so it does not execute. What remains is the config entry and the SDK/AVD sizes being counted as cache.

The android target runs `sdkmanager --update`, which downloads updates and frees nothing. The 20.8 GB SDK and 10.5 GB of AVDs are counted as cache.

### F5 — `brew autoremove` uninstalls packages under a "cache" target (P0)

The brew target describes itself as cache cleanup but runs `brew autoremove`, which uninstalls formulae.

### F6 — Exit code 3 for expected outcomes (P0)

Step 5 exited 3 because one target's command failed. Step 7 exited 3 because the Git safety check skipped six dirs, which is intended behaviour (`dev-cache/main.go` `os.Exit(3)`). Scripts and launchd jobs can't tell partial success from failure.

### F7 — Measured bytes are not cleanable bytes (P1)

| Target | Measured | What clean does |
| --- | --- | --- |
| npm | 2.37 GB (`~/.npm`) | `npm cache clean --force` freed 0.38 GB; 2.1 GB is `~/.npm/_npx`, untouched |
| gradle | 5.5 GB | no command |
| terraform | 1.6 GB | no command |
| xcode | 0.54 GB DerivedData | `xcrun simctl delete unavailable` only |
| docker | 37.9 GB incl. 16.4 GB volumes | volumes are (supposed to be) kept |
| chrome, dropbox, home-cache, pyenv, rustup, cursor, vscode-extensions | 17+ GB | informational only |
| git-cleaner | 3.7 GB | total `.git` size, not what `git gc` would save |

### F8 — Double counting (P1)

`home-cache` (`~/.cache/*`) overlaps `puppeteer` (`~/.cache/puppeteer`, 2.6 GB) and `python-uv` (`~/.cache/uv`). The brew target lists `~/Library/Caches/Homebrew` and `$(brew --cache)`, which resolve to the same directory and show up as two 746 MB findings.

### F9 — Reported freed vs actual freed (P1)

Bilge reported 1.65 GB freed in step 5; the volume gained 3.25 GB. `brew cleanup` also removed `/opt/homebrew/Library/Homebrew/vendor/portable-ruby/*` and `~/Library/Logs/Homebrew/*`, outside the measured paths.

### F10 — dev-cache dry run doesn't apply the Git safety check (P1)

The dry run promised 425 MB; clean freed 345 MB after skipping: two tracked `bin/` dirs, one tracked `vendor/`, one tracked `.yarn/`, and two `dist/` dirs outside any Git repo.

### F11 — dev-cache default depth misses nested repos (P1)

The default `maxDepth: 1` found 0 B across 29 entries in `~/src`, because repos sit at `~/src/<org>/<repo>`. Depth 3 found 5.4 GB.

### F12 — Wrong language labels (P1)

Every Node/Next.js repo was labelled `vue`; Go repos with `bin/` were labelled `dotnet`. Likely cause, to verify: `patternToLang` maps each shared pattern (`node_modules`, `build`, `bin`) to whichever language registers it last, rather than to the project's detected signature. The `bin` pattern then targets Go and shell `bin/` dirs; only the Git safety check stopped tracked ones being deleted.

### F13 — pip resolves to the wrong interpreter (P1)

`pip` resolved to pyenv's Python 2.7.18 (pip 19.2.3), which has no `cache` command, so the python target failed.

### F14 — JSON output problems (P2)

- With `--json`, the full report is also written to stderr (68 KB).
- In clean mode, a task's `output` is a text table inside a JSON string.
- Scan JSON has `commands: {}`, so an agent can't show the user which commands clean would run.
- Top-level `when` is UTC (`Z`); task-level `when` is local time with an offset.

### F15 — Speed and MCP timeouts (P2)

Full scan took 2m54s and a 6-target clean 3m15s, mostly `sys` time from directory walks. MCP tool calls send no progress notifications and could hit client timeouts once F1 is fixed.

### F16 — Smaller UX issues (P2)

- The dev-cache table lists every project with 0 B.
- One task has three names: `mac-cache-cleaner` (config), `bilge-macos` (CLI), `system` (MCP).
- `bilge help dev-cache` prints generic help; only `bilge dev-cache --help` works.
- `bilge_clean` can't run only part of a target (e.g. docker build cache).
- Homebrew cask prints `Calling postflight is deprecated` on every brew command (`homebrew-bilge-pump/Casks/bilge.rb:45`, separate repo).

### F17 — Coverage gaps (P2)

Space found on this machine with no Bilge action: Android 31.3 GB, OrbStack 37 GB on disk, Docker unused images 9.3 GB and unused volumes 7.9 GB, `~/.npm/_npx` 2.1 GB, rustup toolchains 1.9 GB, Terraform plugin cache 1.6 GB, `~/.cache/codex-runtimes` 1.4 GB, pyenv versions 1.0 GB, `~/.cache/pre-commit` 0.73 GB, `~/.cache/act` 0.57 GB.
